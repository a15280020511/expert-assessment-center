# V5 GPT/Claude 专家执行图基线

## 当前唯一治理链

```text
GPT latest：读取原始任务、硬约束和精确端点目录，生成工作项与专家图一次
→ Claude Opus latest：只提出结构化修改建议一次
→ GPT latest：综合一次
→ 确定性宪法校验器：唯一硬门
→ 专家执行
```

禁止第二次 Claude 复审、GPT/Claude 循环、递归修订和无限 Agent 循环。

## 权限边界

### GPT latest

GPT 是动态任务拆解和专家编组的唯一生成者。它自行决定：

- `work_items`、目标、依赖和交付字段；
- 专家数量、角色、函数、工作分配；
- 精确模型与 Provider；
- 执行边、最终节点和恢复顺序。

GPT 只能选择当前任务目录中存在的精确 `model + provider`，不得绕过硬约束。

### Claude Opus latest

Claude 只做一次红队咨询，不拥有批准、否决、放行或阻断权。Claude 不得：

- 选择、替换、增加、删除或排序专家；
- 修改执行图或执行任务；
- 调用工具、浏览、写最终报告；
- 返回 `APPROVE` / `REJECT`；
- 触发第二轮审查。

### 确定性校验器

唯一硬门只验证，不生成或修复方案：

- 工作项依赖为 DAG；
- 每项工作恰好分配一次；
- 工作依赖具有对应节点边；
- 节点、边、阶段、调用和恢复不超过硬上限；
- 模型与 Provider 存在于同一目录快照；
- Provider 单锁并禁止 fallback；
- 专家禁止工具；
- OpenAI 与 Anthropic 不得担任专家；
- 初始专家和恢复专家公司全局唯一；
- 上下文、输出和风险调整费用满足硬边界；
- 用户明确的 JSON、Markdown 或表格交付合同完整。

校验失败时直接失败关闭，不自动放宽、不本地修复。

## 已删除的本地决策层

生产架构不包含：

- 任务领域分类、风险关键词和复杂度评分；
- 本地原子工作生成；
- NumPy 资源矩阵；
- 固定职业、固定席位和固定拓扑；
- OR-Tools / CP-SAT；
- 固定权重、价值比、质量分、Pareto 或候选评分；
- 本地候选排序、裁剪、公司宽度校准；
- 跨端点恢复规划和恢复排序；
- 跨任务历史账本。

## 确定性安全组件

以下组件保留，因为它们不做动态决策：

- `v5_task_envelope.py`：保存任务摘要、硬约束、显式交付合同和容量下限；
- `v5_catalog_view.py`：规范化精确端点目录；
- `v5_proposal_materializer.py`：把 GPT 提案转换为类型化执行图并做硬校验；
- `execution_graph_validator.py`：验证 DAG、覆盖、预算和请求安全；
- `v5_runtime.py`：按已验证图执行专家并生成证据；
- `artifact_manifest.py`：绑定当前架构源码和运行产物哈希。

## 验证纪律

- dry-run 不调用任何模型，也不伪造执行图；
- 所有治理调用和专家调用进入统一请求与费用账本；
- 满载、并发、长任务、依赖环、缺边、未知端点、公司冲突和 Provider 错配必须失败关闭；
- 生产资格门只读，不移动 `main` 或 `production`；
- 真实付费验收必须单独授权并绑定同一提交和 Artifact。
