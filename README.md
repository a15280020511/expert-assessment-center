# Expert Assessment Center

本仓库是正式独立的专家研判中心。GPTs 是本中心与其他业务中心之间唯一的控制与证据中继。

## 最高原则体系

### 1. 任务无关的全动态适应

生产运行时不得包含任何测试题、具体场景名称、样例措辞或由单一案例推导出的固定架构。

禁止在生产逻辑中预设：

- 某类任务固定拆成几个节点；
- 某类任务固定使用哪些职业、红队、裁判或综合角色；
- 固定模型公司数量、固定模型数量或固定 Provider 数量；
- 固定候选池大小、固定排名截断、固定推理强度或固定输出长度；
- 通过测试题关键词直接选择专用流程；
- 为通过某个测试而增加只对该测试成立的规则。

系统只能从当次任务中提取通用变量，并结合当次实时模型市场进行联合计算。任务分解、图结构、节点数量、角色、模型、Provider、公司多样性、参数、预算、复核和恢复方式均是求解变量。

测试任务只能存在于 `tests/`、fixtures 或生成式测试数据中，且不得被生产运行时读取、导入或匹配。

### 2. 性价比最高

在满足当次任务全部硬约束的可行方案中，选择风险调整后任务效用与有效总成本之比最高的方案。

```text
风险调整后的任务效用
÷
（预计模型费用 + 调用开销 + 失败与恢复风险成本）
```

低价不能突破任务契约、能力覆盖、上下文、输出、事实边界、安全、隔离和审计要求。

### 3. 用户显式契约优先

用户明确给出的目标、范围、格式、语言、证据边界、工具边界、费用授权和禁止事项，优先于任何内部模板、默认提示词或历史兼容逻辑。

内部系统不得用通用模板覆盖用户的显式交付契约。

### 4. 全局联合优化，禁止局部贪心

任务解释、原子工作、依赖图、角色、模型、Provider、参数、调用次数、恢复额度、成本和质量必须在同一约束系统中联合求解。

不得先固定节点或角色，再单独选模型；不得先按关键词选流程，再补做优化。

### 5. 最小充分复杂度

系统选择满足任务质量与可靠性要求的最小充分执行图。简单任务不得被无意义扩张，复杂任务不得被不当压缩。

“最小”与“充分”均由任务需求和实时市场计算，不由固定节点数决定。

### 6. 证据化决策，不使用隐藏历史

每次任务只使用：

- 当次任务及其明确输入；
- 当次实时模型、价格、能力和 Provider 快照；
- 当次运行内产生的费用、失败、恢复和质量状态。

禁止跨任务历史权重、隐藏偏好、静默人工名单或不可审计的经验路由影响选模和组团。

### 7. 诚实失败，禁止伪成功

无法满足任务硬约束、交付契约或质量门时必须明确失败关闭，并保留可诊断证据。

不得把未通过质量门的结果包装为完整成功；任何降级交付都必须由当次任务风险与用户许可动态决定，并明确标注缺失与不确定性。

### 8. 可复现、可审计、可解释

相同任务、相同配置和相同市场快照应产生可复现的规划结果。所有重要决策必须输出机器可读证据，包括候选、约束、目标函数、求解状态、替代方案、费用、调用和质量门结果。

### 9. 动态业务决策与固定系统护栏分离

“全动态”不等于“无限执行”。可以固定的仅限与具体任务无关的系统级护栏：

- 专家禁止使用工具、网页、插件、文件搜索、代码执行或其他模型；
- 三中心隔离，禁止隐式跨中心调用；
- 禁止隐藏 Provider fallback、黑箱 Auto Router、Fusion 或备用旧运行时；
- 必须有限执行、异常停止、费用授权、审计回执和失败关闭；
- 生产代码不得包含测试题或场景专用分支。

节点数、调用数、候选池、公司多样性、重试额度等业务参数应由任务动态计算；平台只保留防止失控的绝对紧急上限，且该上限不得充当默认规划值。

### 10. 测试验证通用性质，而不是验证样例答案

测试体系优先使用：

- 属性测试；
- 变形测试；
- 随机任务矩阵；
- 分布外任务；
- 故障注入与并发竞争；
- 预算、上下文、目录规模和 Provider 风暴边界；
- 任务改写后规划不应发生无关突变的稳定性验证。

测试可以保留真实失败案例作为回归输入，但修复必须落在通用机制，不得把案例文本、案例节点或案例答案写入生产逻辑。

## 当前唯一生产运行时

```text
[execution] Issue
→ V5票据授权与去重
→ 任务语义编译
→ 原子工作图
→ 任务资源矩阵
→ OpenRouter实时模型与Provider目录
→ 候选节点矩阵
→ Google OR-Tools CP-SAT联合求解
→ V5动态专家DAG
→ 动态综合与质量门
→ 报告发布、请求审计、费用账本、SHA与Artifact
```

当前代码树只保留 V5 生产运行时。旧固定运行时、旧工作流、旧比较入口、旧测试入口和人工回滚路径均已删除。

系统失败时直接失败关闭，不调用其他运行时。

## 必须动态求解的变量

V5 应根据任务动态计算：

- 任务解释及其不确定性；
- 原子工作、依赖和工作包组合；
- 节点数量、执行阶段、职业和职责；
- 是否需要独立复核、红队、裁判或综合节点；
- 是否需要模型、模型家族、公司或 Provider 多样性；
- 模型、Provider及其明确锁定关系；
- 提示词模块和角色说明；
- reasoning、temperature、verbosity和结构化输出；
- 上下文需求、输出许可和截断风险；
- 候选池范围和求解搜索规模；
- 初始调用、有限重试、替换和恢复；
- 整体费用、质量效用、失败风险和性价比。

10000 Token 仅表示用户允许的输出上界，不是固定请求值，也不是强制输出长度。每个节点的实际额度由任务需求、模型能力和费用动态计算。

## 非任务型系统边界

- 专家执行禁止使用工具；
- 任务必须串行准入并防止重复提交；
- 运行必须有费用授权、异常停止和有限恢复；
- 禁止隐式 Provider fallback；
- 不使用 OpenRouter Auto Router、Fusion 或 Agent 黑箱路由；
- 没有备用运行时回退；
- 运行失败必须明确失败并保留诊断证据；
- 生产运行时禁止导入测试模块、fixture 或场景样例。

## 隔离边界

- 本仓库只运行专家研判中心任务；
- 禁止中心间直接调用、运行时导入、Artifact互取和共享业务 Secret；
- OpenRouter只提供模型目录、Benchmark信息和直接模型调用，不负责路由与选模；
- 生产选模和组团由仓库内可审计的确定性代码完成。
