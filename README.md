# Expert Assessment Center

本仓库是独立的专家研判中心。GPTs 是本中心与其他业务中心之间唯一的控制与证据中继；专家中心不得直接连接其他中心。

最高治理规则见 [`CONSTITUTION.md`](CONSTITUTION.md)。代码、工作流、测试、维护、验收和生产执行均必须遵守该文件，并以失败关闭。

## 当前唯一治理链

```text
GPT latest：读取原始任务、硬约束和精确模型端点目录，生成工作项与专家执行图一次
→ Claude Opus latest：只提出结构化红队修改建议一次
→ GPT latest：综合一次
→ 确定性宪法校验器：唯一硬门
→ 专家执行
→ 完整审计、Manifest、Artifact 和最终回执
```

固定治理模型：

- GPT：`~openai/gpt-latest`
- Claude：`~anthropic/claude-opus-latest`

固定治理调用：

```text
GPT 提案 1 次
Claude 红队建议 1 次
GPT 综合 1 次
合计 3 次
```

禁止第二次 Claude 复审、GPT/Claude 循环、递归修订和无限 Agent 循环。

## 动态决策边界

GPT 根据每次任务和当次精确端点目录，自行决定：

- `work_items`、目标、依赖和交付字段；
- 专家数量、角色、函数和工作分配；
- 精确模型与 Provider；
- 执行边、最终节点和恢复顺序；
- reasoning 强度和可见输出额度。

生产代码不得预设任务领域、任务复杂度、固定职业、固定席位、固定拓扑、固定质量权重或固定专家组合。

## Claude 权限

Claude 只做一次咨询型红队，输出严格结构化修改意见。Claude 不得：

- 返回 `APPROVE` / `REJECT`；
- 批准、否决、放行或阻断任务；
- 选择、替换、增加、删除或排序专家；
- 修改执行图或执行任务；
- 调用工具、浏览网络或写最终报告；
- 触发第二轮红队。

## 确定性硬约束

确定性校验器只验证，不生成、不评分、不排序、不修复 GPT 方案。它负责：

- 工作依赖必须为 DAG；
- 每项工作恰好分配一次；
- 跨节点工作依赖必须存在对应执行边；
- 模型与 Provider 必须存在于同一目录快照；
- Provider 必须单锁并禁止 fallback；
- 专家禁止使用工具；
- OpenAI 与 Anthropic 不得担任专家；
- 初始专家与恢复专家的模型公司全局唯一；
- 节点、边、阶段、调用、恢复和费用不超过硬上限；
- 上下文和可见输出额度满足端点能力；
- 用户明确的 JSON、Markdown、表格和完整交付合同必须满足；
- 事实、假设、推断、来源和封闭世界数量边界必须通过独立审计。

任何硬约束失败都直接失败关闭，不自动放宽。

## 已删除的旧决策层

当前生产架构不包含：

- 本地任务领域分类、风险关键词和复杂度评分；
- 本地语义解释和原子工作生成；
- NumPy 资源矩阵；
- OR-Tools / CP-SAT；
- 固定权重、价值比、质量评分和 Pareto 裁剪；
- 本地候选排序、候选宽度或公司宽度校准；
- 本地动态参数求解；
- 跨端点恢复规划和恢复排序；
- 跨任务历史账本；
- 固定专家、固定红队、固定裁判或固定综合席位；
- 旧兼容执行器和备用生产运行时。

仓库回归门会阻止这些模块、依赖、导入和旧产物名称重新进入生产代码。

## 保留的确定性组件

- `v5_task_envelope.py`：保存任务摘要、硬约束、明确交付合同和容量下限；
- `model_market.py`：读取并规范化模型目录，不进行任务分类或选模；
- `v5_catalog_view.py`：生成精确 `model + provider` 目录视图；
- `v5_gpt_expert_selector.py`：固定 GPT 提案与综合协议；
- `v5_claude_red_team_policy.py`：固定 Claude 一次性咨询协议；
- `v5_governance_runtime.py`：执行固定 GPT→Claude→GPT 治理顺序并记录调用；
- `v5_proposal_materializer.py`：将 GPT 提案转换为类型化执行图并执行硬校验；
- `execution_graph_validator.py`：验证图、覆盖、预算、公司和请求安全；
- `v5_runtime.py`：执行已经验证的专家图并生成证据；
- `artifact_manifest.py`：绑定运行产物和当前架构源码哈希。

## 运行纪律

- 开发、维护、排错、回归和压力测试必须先完成零调用确定性验证，再使用费用严格为 `0.0 USD` 的免费模型 Canary；
- 付费模型只用于正式生产任务或用户明确授权的一次性最终付费验收，失败后禁止自动重试；
- 免费模型证据不得冒充正式模型身份验收，也不得单独移动 `production`；
- 单任务串行准入；未完成任务不得并发进入生产执行；
- 专家禁止工具、浏览器、插件、文件搜索和代码执行；
- 所有治理调用和专家调用进入统一请求、调用和费用账本；请求正文只保存哈希、长度和结构回执，不在治理账本重复保存原始任务或完整目录；
- dry-run 不调用任何模型，也不伪造执行图；
- 生产执行只使用检出后的权威源码 SHA；
- 审计失败、Manifest 失败或 Artifact 失败时不得发布报告；
- 付费验收必须绑定同一提交、同一运行和同一 Artifact digest；
- `main` 与 `production` 只能在明确验收后移动。

## 验证范围

零费用验证包括：

- Ruff 与 Python compileall；
- 全量单元测试；
- 执行图、公司唯一性、Provider 锁和工具禁用测试；
- 调用、恢复、费用和并发竞争测试；
- 任务隔离与重复提交测试；
- 明确 JSON / Markdown 合同与最终节点隔离测试；
- 封闭世界数量、事实来源和推断边界测试；
- 12 个初始专家节点的满额图；
- 512 次并发确定性物化；
- 依赖环、缺边、未知端点、公司冲突和 Provider 错配故障注入；
- 近 5 万字符任务的重复 dry-run；
- GPT→Claude→GPT 固定三次调用的假响应端到端测试；
- 防止旧本地规划模块和依赖回流的仓库级审计。

真实模型验收与零费用结构验收分离；未明确授权时不得触发付费模型调用。
