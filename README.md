# Expert Assessment Center

本仓库是正式独立的专家研判中心。GPTs 是本中心与其他业务中心之间唯一的控制与证据中继。

## 最高原则体系

### 1. 任务无关的全动态适应

生产运行时不得包含任何测试题、具体场景名称、样例措辞或由单一案例推导出的固定架构。

禁止在生产逻辑中预设：

- 某类任务固定拆成几个节点；
- 某类任务固定使用哪些职业、红队、裁判或综合角色；
- 固定模型数量或固定 Provider 数量；
- 固定候选池大小、固定排名截断、固定推理强度或固定输出长度；
- 固定模型评分权重或固定任务适配特征权重；
- 固定任务解释数量、质量容差、阶段数或边数；
- 通过测试题关键词直接选择专用流程；
- 为通过某个测试而增加只对该测试成立的规则。

系统只能从当次任务中提取通用变量，并结合当次实时模型市场进行联合计算。任务分解、图结构、节点数量、能力、角色、模型、Provider、参数、目标权重、质量容差、预算、复核和恢复方式均是求解变量。

测试任务只能存在于 `tests/`、fixtures 或生成式测试数据中，且不得被生产运行时读取、导入或匹配。

### 2. 同一任务必须使用不同公司的模型

这是任务无关的固定治理边界，不是测试特例，也不由任务内容决定是否启用。

- 一个任务只选择一个模型时，该约束自然满足；
- 一个任务选择两个及以上模型时，所有已选模型的所属公司必须全局互不重复；
- 初始节点、红队、裁判、综合节点、复核节点和恢复替换节点全部纳入同一公司唯一性约束；
- 终局审计纳入所有实际调用，包括失败调用、重试和恢复调用；
- 同一节点的有限重试不视为第二名专家，但不得借重试形成跨节点公司复用；
- 同一家公司旗下不同模型、不同模型家族、不同版本或不同 Provider 端点，仍视为同一家公司；
- Provider 不同不能替代模型公司不同；
- 候选公司不足时必须扩大候选搜索范围；扩大后仍不足则明确失败关闭，不得放宽为同公司模型；
- 每次运行必须输出模型公司归一化结果、全部实际调用、冲突检查和最终公司集合审计。

模型数量、节点数量和是否需要红队、裁判或综合节点仍由当次任务动态计算；一旦选择多个模型，公司全局互异就是不可突破的硬约束。

### 3. 性价比最高

在满足当次任务全部硬约束的可行方案中，选择风险调整后任务效用与有效总成本之比最高的方案。

```text
风险调整后的任务效用
÷
（预计模型费用 + 调用开销 + 失败与恢复风险成本）
```

低价不能突破任务契约、能力覆盖、上下文、输出、事实边界、安全、跨公司模型隔离和审计要求。

### 4. 用户显式契约优先

用户明确给出的目标、范围、格式、语言、证据边界、工具边界、费用授权和禁止事项，优先于任何内部模板、默认提示词或历史兼容逻辑。

任务约束必须编译为机器可读对象。中文与英文授权均按以下极性执行：

```text
明确禁止 > 明确允许 > 默认禁止
```

因此“不允许部分结果”“不能接受不完整交付”“只接受完整交付”均不得被字符串子匹配误判为允许降级。

### 5. 事实、假设与推断严格分离

结构完整不等于证据真实。质量门必须分别验证：

- 输出合同是否完整；
- 事实标签是否有题面证据支撑；
- 上游模型推断是否被错误提升为事实；
- 封闭世界任务是否引入题面没有的精确数量；
- 外部事实、来源归属和证据边界是否符合结构化约束。

仅依据题面、不得调用外部工具、不得编造等约束必须同时作用于节点输出、最终报告和独立审计。`full_success` 只有在结构、证据和治理均通过时才成立。

### 6. 全局联合优化，禁止局部贪心

任务解释、原子工作、依赖图、能力、模型、Provider、参数、调用次数、恢复额度、成本和质量必须在同一约束系统中联合求解。

不得先固定节点或角色，再单独选模型；不得先按关键词选流程，再补做优化。模型公司全局唯一性必须直接进入联合求解器，而不是在求解完成后补做过滤。

### 7. 最小充分复杂度

系统选择满足任务质量与可靠性要求的最小充分执行图。简单任务不得被无意义扩张，复杂任务不得被不当压缩。

“最小”与“充分”均由任务需求和实时市场计算，不由固定节点数决定。跨公司硬约束不得被用作强制增加节点的理由；它只约束已经被动态选择的多个模型。

### 8. 证据化决策，不使用隐藏历史

每次任务只使用：

- 当次任务及其明确输入；
- 当次实时模型、价格、能力、公司归属和 Provider 快照；
- 当次运行内产生的费用、失败、恢复和质量状态。

禁止跨任务历史权重、隐藏偏好、静默人工名单或不可审计的经验路由影响选模和组团。

### 9. 诚实失败，禁止伪成功

无法满足任务硬约束、跨公司模型隔离、交付契约或质量门时必须明确失败关闭，并保留可诊断证据。

不得把未通过质量门的结果包装为完整成功；任何降级交付必须得到用户显式授权，并明确标注缺失与不确定性。不得通过改用同公司模型来制造伪成功。

### 10. 可复现、可审计、可解释

相同任务、相同配置和相同市场快照应产生可复现的规划结果。所有重要决策必须输出机器可读证据，包括候选、模型公司归一化、公司冲突矩阵、约束、动态权重、目标函数、求解状态、替代方案、费用、调用和质量门结果。

执行源码 SHA 以检出后的 `git rev-parse HEAD` 为权威，不以事件 `GITHUB_SHA` 代替。Manifest 中每个文件必须记录大小和 SHA-256。

### 11. 动态业务决策与固定系统护栏分离

“全动态”不等于“无限执行”。可以固定的仅限与具体任务无关的系统级护栏：

- 专家禁止使用工具、网页、插件、文件搜索、代码执行或其他模型；
- 三中心隔离，禁止隐式跨中心调用；
- 同一任务使用多个模型时，模型所属公司必须全局互不重复；
- 禁止隐藏 Provider fallback、黑箱 Auto Router、Fusion 或备用旧运行时；
- 必须有限执行、异常停止、费用授权、审计回执和失败关闭；
- 生产代码不得包含测试题或场景专用分支。

节点数、调用数、候选池、模型数量、Provider 多样性和重试额度等业务参数应由任务动态计算；平台只保留防止失控的绝对紧急上限，且该上限不得充当默认规划值。

### 12. 审计先于公开发布

正式顺序固定为：

```text
执行
→ 生成全部业务证据
→ 准备报告发布包
→ 完整执行审计
→ 审计 PASS
→ 冻结 Manifest
→ 上传主 Artifact
→ 公开报告
→ 生成最终 Attestation
```

任何审计失败、Manifest 失败或 Artifact 失败都必须阻止公开报告。

### 13. 独立验收必须从底层证据重算

付费验收不得只读取第一阶段 verdict。独立复核必须从原始节点、请求、实际费用、报告、结构化约束、Manifest 文件哈希和下载 ZIP digest 重建结论。

验收请求必须绑定目标 SHA、任务、质量兼容标签、调用上限、恢复上限和费用异常上限；不得硬编码旧分支、旧 PR 或固定验收题。

### 14. 测试验证通用性质，而不是验证样例答案

测试体系优先使用：

- 属性测试；
- 变形测试；
- 随机任务矩阵；
- 分布外任务；
- 故障注入与并发竞争；
- 预算、上下文、目录规模和 Provider 风暴边界；
- 公司别名归一化、同公司伪装、恢复替换冲突和候选公司不足测试；
- 任务改写后规划不应发生无关突变的稳定性验证。

测试可以保留真实失败案例作为回归输入，但修复必须落在通用机制，不得把案例文本、案例节点或案例答案写入生产逻辑。

## 当前唯一生产运行时

```text
[execution] Issue
→ V5票据授权与去重
→ 结构化任务约束编译
→ 任务语义编译
→ 原子工作图
→ 任务资源矩阵
→ OpenRouter实时模型与Provider目录
→ 动态模型适配与目标权重
→ 模型公司归一化与候选节点矩阵
→ Google OR-Tools CP-SAT联合求解（含任务级公司全局唯一约束）
→ V5动态专家DAG
→ 节点合同与证据质量门
→ 最终证据与全部实际调用公司终审
→ 完整审计、Manifest、Artifact
→ 审计通过后公开报告与最终Attestation
```

正式生产工作流只调用宪法 V5 入口。旧兼容模块不属于生产入口，不得被工作流、票据或发布资格门调用。系统失败时直接失败关闭，不调用其他运行时。

## 必须动态求解的变量

V5 根据当次任务动态计算：

- 任务解释数量及其不确定性；
- 原子工作、依赖和工作包组合；
- 节点数量、执行阶段、职业能力和职责；
- 是否需要独立复核、红队、裁判或综合节点；
- 模型数量以及是否需要模型家族或 Provider 多样性；
- 模型、Provider及其明确锁定关系；
- 提示词模块和角色说明；
- reasoning、temperature、verbosity和结构化输出；
- 上下文需求、输出许可和截断风险；
- 候选池范围和求解搜索规模；
- 模型总目标权重和任务适配特征权重；
- 质量容差、工作覆盖率、最低成功节点、阶段数和边数；
- 初始调用、有限重试、替换和恢复；
- 整体费用、质量效用、失败风险和性价比。

模型公司是否互异不是动态变量：只要选中多个模型，就必须满足任务级公司全局唯一约束。

10000 Token 仅表示用户允许的输出上界，不是固定请求值，也不是强制输出长度。每个节点的实际额度由任务需求、模型能力和费用动态计算。

## 非任务型系统边界

- 专家执行禁止使用工具；
- 任务必须串行准入并防止重复提交；
- 同一任务内的所有已选模型必须来自不同公司；
- 所有实际调用，包括失败调用，纳入跨节点公司唯一性终审；
- 恢复模型不得与任何其他节点已选或已使用模型公司冲突；
- 运行必须有费用授权、异常停止和有限恢复；
- 禁止隐式 Provider fallback；
- 不使用 OpenRouter Auto Router、Fusion 或 Agent 黑箱路由；
- 没有备用运行时回退；
- 运行失败必须明确失败并保留诊断证据；
- 生产运行时禁止导入测试模块、fixture 或场景样例；
- `main != production` 时生产控制面失败关闭。

## 隔离边界

- 本仓库只运行专家研判中心任务；
- 禁止中心间直接调用、运行时导入、Artifact互取和共享业务 Secret；
- OpenRouter只提供模型目录、Benchmark信息和直接模型调用，不负责路由与选模；
- 生产选模和组团由仓库内可审计的确定性代码完成。
