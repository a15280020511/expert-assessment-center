# V5 R8 生产替代加固与验收基线

## 结论

R8 已把 R6 暴露的主要架构缺陷转化为可测试的运行时约束，但在完成小额真实盲评前，V5 仍是候选版本：

```text
V3 生产入口：保留
V5 生产入口：未切换
V3 删除：禁止
自动付费测试：暂停
```

代码通过只能证明实现和离线行为正确，不能证明 OpenRouter 实际 Provider、模型输出和费用分布已经满足生产门。

## R6 原始 Artifact 离线回放

| 任务 | 计划节点 | 已执行 | 有答案节点 | 内容覆盖 | high 推理请求 | 严格 JSON 请求 | 10000 上限请求 | V5 实际费用 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 零售扩张 | 9 | 5 | 1 | 1/6 = 16.7% | 5/5 | 0/5 | 5/5 | 0.02167 USD |
| 公共卫生谣言 | 10 | 8 | 7 | 5/7 = 71.4% | 8/8 | 0/8 | 8/8 | 0.20399593 USD |
| 软件任务执行器安全 | 9 | 7 | 2 | 1/6 = 16.7% | 7/7 | 7/7 | 7/7 | 0.51142188 USD |

离线结论：

1. 公共卫生题已有 71.4% 内容覆盖。旧执行器因单节点失败返回整题失败；R8 会明确标记为降级成功并确定性合成。
2. 零售题和安全题的现有结果覆盖不足，R8 不会把它们误判为成功，必须通过替换节点或新执行结果补足覆盖。
3. 安全题所有请求同时使用 high 推理、严格 JSON 和 10000 最大许可，是费用放大与 JSON 截断的直接组合风险。
4. 安全题实际费用 0.51142188 USD，相对 0.14301981 USD 的执行前估算约为 3.58 倍，并超过 0.25 USD 单策略限制。旧估算没有充分计入推理 Token 和失败恢复尾部风险。

## R6 暴露的缺陷

### P0：可用性

- 任一必需节点失败导致整图不交付。
- 失败后没有按 429、5xx、超时、空答、截断、无效 JSON 分类处理。
- 严格 JSON 失败可能被长文本误当成“可用输出”。
- 最终综合节点没有预算保护，前置节点可以耗尽余额。

### P0：成本安全

- 费用估算主要依据正文输出，低估推理 Token。
- 10000 Token 最大许可与 high reasoning 同时作用，部分模型会把大量许可用于计费推理。
- 估算预留在实际费用回执后没有正确释放，运行账本可能高估或错误拒绝后续调用。
- 只有图级均值，没有 P95 风险上界、历史空答率和 Provider 可靠性修正。

### P1：性能

- 普通分析、证据核验和最终综合普遍使用同一 high 推理强度。
- 高风险结构化任务把严格 JSON 下推到全部中间节点，增加截断和格式失败概率。
- 上游结果按字符前缀裁切，可能破坏 JSON 闭合并丢失末尾结论。
- 有硬预算时全阶段串行，稳定但增加延迟；后续可在预算余量充分时恢复有限并行。

### P1：治理

- 生产切换与 V3 删除没有分成两个独立证据门。
- 三题比较不足以证明长期 Provider 稳定性、费用漂移和降级率。
- Provider 集中度缺少“先重平衡、无替代则告警、明确要求时才硬拒绝”的分层策略。

## R8 已实现

### 1. 推理强度按工作价值分配

- 综合裁决、定量建模、工程实现、红队、反事实可使用 high。
- 普通分析、证据核验、预测和决策比较默认 medium。
- 简单分析进一步降到 low/medium 区间。
- 10000 Token 保持为最大许可，不是目标输出；节点根据工作量动态计算实际请求上限。

### 2. 严格 JSON 只在交付边界使用

- 中间专家节点以稳定文本输出为主。
- 单节点直接交付或 synthesis 最终节点才强制严格 JSON。
- 对支持结构化参数的 Endpoint 强制 `require_parameters=true`。
- 无效或截断 JSON 永不作为普通文本降级成功。

### 3. 故障分类恢复

| 故障 | R8 行为 |
|---|---|
| HTTP 429 | 不在同 Endpoint 重试，优先跨 Provider/模型替换 |
| 502/503/504/超时 | 最多一次同 Endpoint 重试，再替换 |
| 空答 | 直接进入替换候选 |
| JSON 截断/无效 | 严格结构化节点不可降级为文本，进入替换 |
| 普通文本质量门不足但正文完整 | 可作为低质量候选，仅在恢复失败后明确降级使用 |
| Provider 连续失败 | Endpoint 熔断，后续节点不再继续调用该 Endpoint |

所有重试和替换仍受全局次数、实际费用和风险预算共同约束。

### 4. 风险成本与最终节点保护

- 估算包含预期正文 Token、推理 Token、历史空答/截断/限流率和 Endpoint 可靠性。
- 图级默认风险系数为 1.35。
- 风险上界超出硬预算时，在第一次模型调用前拒绝并生成审计 Artifact。
- 实际费用回执后释放对应估算预留。
- 非最终节点不得消耗已保护的最终综合节点预算。
- 费用达到硬上限后不再启动新调用。

### 5. Provider 多样性

- 优先从 recovery pool 选择跨 Provider 的低风险替代。
- 能重平衡时，在执行前完成替换。
- 没有安全替代时默认记录告警，避免因市场暂时只有一个可靠 Provider 而完全不可用。
- 任务显式设置 `provider_diversity_required=true` 时，集中度超限成为硬阻断。

### 6. 覆盖率降级交付

- 最终节点不能掩盖缺失的上游内容工作。
- 默认至少覆盖三分之二内容工作，且不得缺失 `non_degradable_work_ids`。
- 有效最终答案存在但上游不完整时，标记 `degraded_success`。
- 最终节点失败但内容覆盖达标时，使用已成功节点确定性合成，不增加模型调用。
- 结构化任务的确定性合成保持合法 JSON 顶层字段。
- 覆盖不足时仍然失败，禁止“有一点文字就算成功”。

### 7. 切换与删除双门

#### 生产切换门

- 3 个独立真实盲评任务全部可交付；
- 0 个安全、预算、JSON、裁判致命错误；
- 匿名质量不低于 V3；
- 若费用高于 V3，性价比至少提高 10%；
- 随后完成 20 个 V5 Canary 任务，致命失败为 0，降级率不高于 1/3。

#### V3 删除门

只有 V5 成为默认入口后，再观察至少 30 个正式任务：

- 无生产级回归；
- 无预算越界；
- 无严格 JSON 致命失败；
- 质量和性价比继续满足门槛；
- 单独创建删除 V3 的 Issue 与 PR。

生产切换许可和 V3 删除许可由不同字段输出，禁止一次操作同时完成。

## 零费用验收范围

PR #65 必须通过：

- Python 编译与 Ruff 静态检查；
- 全仓库 `unittest discover`；
- V5 优化器和 DAG 确定性 dry-run；
- 429 跨 Provider 恢复；
- 严格 JSON 截断拒绝；
- 风险预算 0 调用拒绝；
- 推理分级和动态 Token 许可；
- Provider 重平衡与无替代告警；
- 切换门与删除门分离；
- 完整仓库逐行审计和专家团完整性校验。

## 尚未证明的事项

- R8 对 OpenRouter 当前真实 Provider 的成功率尚未通过付费盲评证明。
- 新成本估算的 P50/P95 校准尚无足够真实样本。
- 不同模型对动态最大 Token 与 reasoning effort 的实际消耗仍存在差异。
- 三题结果不能替代 20 题 Canary 与 30 题默认后观察。

因此，合并 R8 代码不等于批准生产切换。
