# V5低成本试运行 Run 30525545840 复盘

## 结论

Issue #28 的首轮试运行在任何模型调用前停止：

- 全仓单元测试、Ruff、编译和依赖检查通过；
- OpenRouter Secret存在；
- 0.50 USD低成本额度预检通过；
- CP-SAT求解状态为`INFEASIBLE`；
- 模型调用0次；
- 实际费用0 USD；
- 生产入口未改变。

这不是模型质量失败，也不是Provider调用失败。

## 根因

任务`retail-expansion-unit-economics`被资源编译器拆成6个工作单元：

- 4个高重要性分析单元各要求2个独立副本；
- 1个独立红队单元；
- 1个综合裁决单元。

因此V5执行图至少需要约10个节点，并同时满足：

- 每个工作副本完整覆盖；
- 独立副本不得复用同一模型；
- 独立副本不得复用同一Provider Endpoint；
- 能力硬门槛；
- DAG边和阶段限制；
- 节点与调用上限；
- V5原单策略预计费用上限0.12 USD。

低价模型过滤本身仍产生了候选，但在0.12 USD预计预算下无法选择完整执行图。

## 修复

不降低能力、独立性、工作单元或质量要求，改为总额内动态预算：

```text
总实际费用上限：0.50 USD（不变）
V5初始规划额度：总额60% = 0.30 USD
V5最大规划额度：总额70% = 0.35 USD
保留给V3、其他基线和裁判：至少0.15 USD
```

如果初始预算不可行：

1. 在0次模型调用状态下移除预算约束，计算质量带内最低预计成本；
2. 若结构在无预算情况下也不可行，报告候选/Provider结构问题；
3. 若结构可行且最低预计成本不超过0.35 USD，按最低成本加3%缓冲重试；
4. 若超过0.35 USD，停止，不降低质量或独立性；
5. 全局实际费用和40次调用硬上限继续生效。

## 不变边界

- V3生产入口不变；
- V5生产切换资格为false；
- 完整五任务盲评仍为正式切换前置条件；
- 低成本试运行不能作为V5优于V3的证据。
