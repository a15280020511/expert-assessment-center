# V5 专家团中心动态参数与代码审计（R9）

## 结论

V5 已经不是固定 3+1 专家团，而是任务语义编译、原子工作图、模型端点市场与 CP-SAT 联合优化形成的动态执行图。

但“除禁止工具外全部不设限制”不是正确目标。系统必须保留有限预算、有限调用、有限图规模、上下文边界、显式 Provider、输出契约、审计与生产资格门等硬约束，否则会重新引入无限循环、失控费用和不可审计执行。

正确架构是：

```text
不可优化的硬安全边界
＋
边界以内全部任务化、端点化、风险化动态计算
```

本轮将职业、推理档、支持的采样参数和优化器迭代次数进一步动态化，并修复 R8H 暴露的预算口径和止损问题。

## 二、全面参数表

### A. 永久硬约束，不允许动态取消

| 参数 | 当前策略 | 原因 |
|---|---|---|
| 工具、插件、浏览器、搜索、代码执行 | 永久禁止 | 专家团隔离原则 |
| OpenRouter 路由模型、online/batch 变体 | 禁止 | 保证直接模型和端点审计 |
| Provider | 必须显式 `order/only`，关闭 fallback | 防止不可见路由 |
| 总费用上限 | 由请求或工作流给出 | 防失控费用 |
| 总调用上限 | 有限 | 防无限 Agent 循环 |
| 最大节点、边、阶段 | 有限 | 防图爆炸和死循环 |
| 最大上下文 | 不超过端点能力 | API 合法性 |
| 输出许可 | 不超过端点与治理上限 | 防截断同时防失控 |
| 输出契约和 Schema 校验 | 必须 | 可交付性和机器审计 |
| 请求、费用、模型、Provider、结果 Artifact | 必须记录 | 可追溯性 |
| Stage-D、Canary、默认观察、V3 删除门 | 独立治理 | 不能由优化器自行绕过 |

### B. 已动态计算的任务与组织参数

| 参数 | 输入 | 计算方式 | 硬边界 |
|---|---|---|---|
| 任务领域 | 题目、显式领域 | 领域信号矩阵 | 最多保留高权重 4 个 |
| 认知操作 | 题目、风险、复杂度 | 操作需求矩阵 | 必须覆盖分析基线 |
| 原子工作 | 领域×操作×依赖 | 三种解释方案比较 | 有限解释数 |
| 专家职业/角色 | 主领域、次领域、操作权重 | 动态复合角色字符串与能力向量 | 不使用固定席位 |
| 专家数量 | 工作覆盖、冗余、预算、节点上限 | CP-SAT 选择节点 | Stage-D ≤9，生产默认 ≤16 |
| 专家组合方式 | 原子工作依赖和独立性 | DAG 拓扑优化 | 无环、有限阶段 |
| 独立副本数 | 高风险、证据核验、红队要求 | 1 或 2 个显式副本 | 不允许无限副本 |
| 模型 | 实时 Top 排名、任务拟合、价格、上下文 | 候选市场＋CP-SAT | 直接文本模型 |
| Provider 端点 | 真实端点价格、可靠性、参数支持 | 模型端点联合候选 | 显式 Provider |
| 提示词模块 | 工作的提示需求向量 | 超阈值模块组合 | 禁止工具规则固定注入 |
| 推理深度 | 操作、复杂度、高风险、错误成本 | 连续 0–1 分数 | 映射到端点支持档位 |
| 推理档 | 深度、重要性、错误成本 | 控制分数映射 low/medium/high | 端点支持时发送 |
| temperature | 验证强度、创造性、结构化输出 | 0–0.85 动态 | 仅端点支持时发送 |
| top_p | 控制/探索需求 | 0.85–0.95 动态 | 仅端点支持时发送 |
| presence penalty | 创意探索需求 | 0–0.35 动态 | 仅端点支持且创意任务 |
| frequency penalty | 验证型任务 | 固定为 0 避免不必要扰动 | 仅端点支持时发送 |
| 输出契约 | 工作操作类型 | 字段集合动态合并 | 最终交付边界可强制 JSON |
| 输出许可 | 预期输出、推理、端点最大值 | completion envelope | R8 上限 10000 |
| 预计计费 Token | 输出＋推理 Token | P95 风险估计 | 不把最大许可当实际使用 |
| 上下文分配 | 原题、系统提示、可见上游、推理、输出 | 节点级预算 | 不读取未声明节点 |
| 优化器迭代数 | 候选数量、求解时间 | 4–18 自适应 | 有限、确定性 |
| Provider 多样性 | 端点集中度、替代成本、风险 | 预算安全时重平衡 | 默认软目标，显式要求才硬失败 |
| 可靠性替换 | 节点失败概率、恢复池 | 更低风险且整图预算安全 | 总替换上限 |
| 重试 | 错误分类、全局账本 | 仅可恢复错误 | Stage-D 全局上限 1 |

### C. 仍为固定或半动态、不可伪称“完全动态”的参数

| 参数 | 当前固定项 | 判断 |
|---|---|---|
| 语义关键词字典 | 领域与操作关键词 | 确定性基础，但需基准校准 |
| 解释方案种类 | 操作拆解、领域拆解、混合拆解 | 候选有限，属于安全设计 |
| 最大解释数 | 3 | 可按歧义度动态缩减，不能无限增加 |
| 最大领域数 | 4 | 安全和成本上限 |
| 独立副本最大数 | 2 | 防止组合爆炸 |
| 质量、风险、能力权重 | 多处经验权重 | 需要冻结基准和历史校准 |
| Stage-D 节点、重试、替换上限 | 9、1、2 | 验收治理，不应由任务取消 |
| Provider 最大占比 | 默认 0.60 | 软目标，可按市场可用性校准 |
| 最低可靠性 | 默认 0.80/生产阈值 | 硬资格线，需要历史数据校准 |

## 三、R8H 根因和修复后的统一公式

旧流程：

```text
优化器：raw_cost <= 0.25
运行时：rebalance(raw_graph) × risk_multiplier <= 0.25
```

新流程：

```text
planning_raw_budget = hard_runtime_budget / cost_risk_multiplier
优化器：raw_cost <= planning_raw_budget
可靠性替换：替换后 raw_cost <= planning_raw_budget
Provider 重平衡：替换后 raw_cost <= planning_raw_budget
运行时：final_raw_cost × cost_risk_multiplier <= hard_runtime_budget
```

因此，任何能通过零调用门的图必须能通过同一份 runtime preflight；若不能，整个比较在第一次模型调用前终止。

## 四、比较器止损模型

旧顺序：

```text
每题：V5 → V3 → 匿名裁判
```

新顺序：

```text
第一阶段：三题只运行 V5
任一题失败：立即停止；V3=0；裁判=0
三题全部成功：第二阶段运行 V3 和匿名裁判
```

这不能追回已经发生的 V5 调用费用，但可以消除失败后继续比较造成的无效费用。对 R8H 的零调用预检失败模式，预期无效下游调用从 9 降为 0，无效下游费用从 0.76874651 美元降为 0。

## 五、仿真验收场景

`v5_preflight_simulation.py` 固定覆盖：

1. R8H 原始预算可见但风险预算不可行；
2. Provider 替换在预算内，允许重平衡；
3. Provider 替换超预算且多样性为软目标，保留原图；
4. Provider 替换超预算且多样性显式为硬要求，失败关闭。

仿真不调用模型，实际费用为 0。

## 六、尚未删除的重复代码

本轮没有直接删除以下兼容层：

- `v5_planner.py` 内旧优化器；
- 多代 low-cost pilot 和 benchmark 封装；
- V3 固定席位分类与执行代码；
- 多个生产 hardening installer。

原因不是这些代码都必要，而是当前尚未完成 Stage-D、20 题 Canary 和 30 题默认观察。此时大规模删除会提高回归风险，并破坏 V3 回滚能力。

后续删除条件：

```text
Stage-D 通过
＋20题 Canary 通过
＋V5 默认 30 题观察通过
＋V3 回滚快照验证完成
```

在这些条件前，V3 删除仍然禁止。
