## 根因

候选数量和Provider数量已经充足，瓶颈是能力测量方式：

- 领域能力主要由模型目录的名称和营销描述关键词推断；
- 强通用模型的描述经常不出现`business`、`security`、`research`或`math`等词；
- 领域分数因描述缺词被低估；
- 任务矩阵同时要求定量推理、证据验证、决策比较、风险发现等功能能力；
- 模型可能具备这些任务所需功能能力，但因领域标签低估而无法进入候选图。

这不是降低任务标准的理由，而是能力测量证据不足。

## 修复方案

### 1. 任务矩阵动态领域代理

对每个任务动态计算：

```text
领域需求
× 同一工作单元中的功能能力需求
× 双方需求置信度
→ 领域—功能能力代理权重
```

例如，只有当本任务的`domain:business`与定量推理、证据验证、决策比较等需求共同出现时，这些功能能力才可作为业务领域迁移证据。

不预设固定职业或固定模型名单。

### 2. 只校准领域测量

- 功能能力原始分数不变；
- 领域原始分数保留；
- 任务代理分数单独记录；
- 使用模型基准置信度对代理分数折减；
- 校准分数取原始领域分数与置信度折减代理分数的较大值；
- 所有Endpoint逐项记录原始值、代理值、校准值和权重。

### 3. 硬门不变

规划器仍使用：

```text
max(0.48, 0.62 × minimum_demand)
```

以下均不改变：

- 任务需求矩阵；
- 原子工作数量；
- 独立副本数量；
- 模型与Provider独立性；
- 质量要求；
- 总费用0.50 USD；
- V5规划最高0.35 USD；
- 总调用40；
- 生产切换资格false。

### 4. 硬门差距报告

若校准后仍无候选，Artifact将逐工作、逐硬能力报告：

- 规划阈值；
- 原始最高分；
- 校准最高分；
- 通过Endpoint数；
- 通过模型数；
- 同时通过全部硬能力的Endpoint数；
- 上下文和输出容量合格数。

这样下一步可区分领域评分低估、核心能力不足、上下文不足或真实Provider缺口。
